# Feishu to Codex Desktop Bridge

Experimental macOS bridge that routes Feishu bot messages into **native Codex Desktop chats**, keeps questions and answers in a local Codex project, and replies in Feishu. Follow-up messages reuse the same chat; `新会话：` starts a new one.

An optional document-comment channel receives explicit `@bot` mentions through `drive.notice.comment_add_v1`. It reads the mentioned comment and, for accessible Docx files, the document body using the bot's own permissions. Each document comment has a separate native Codex chat. Local comments get an in-place reply; whole-document comments require a new linked whole-document comment because Feishu does not allow replies to them. One whole-document Docx comment has passed a live end-to-end test on a Mac: Feishu comment → native Codex chat → Feishu comment answer. Other document types and a clean-install setup remain unverified. New installations still need comment scopes, event subscription, document access, and publication. The repository can build a temporary pinned Feishu CLI with comment-event support without replacing the system CLI. See the Chinese guide for setup.

Only deliberate bot interactions are treated as questions. Ordinary document edits, member changes, and read receipts are ignored. Custom bot menus and interactive cards are not currently configured, so their events have no request flow yet.

The repository now includes a desktop-only Codex plugin with an onboarding skill. On a Mac with Codex CLI, run `curl -fsSL https://raw.githubusercontent.com/bearea/feishu-codex-desktop-bridge/main/install.command | zsh`, then open the plugin setup flow in Codex Desktop. The installer adds the plugin; the guided flow handles Feishu app creation, browser configuration, local service setup, and real-message validation. A fresh-machine, fresh-tenant end-to-end installation has **not yet been validated**. Feishu login and organization approval still require the appropriate person.

This repository implements the Feishu adapter only. The core pattern can be adapted to Slack, Teams, and other messaging platforms, but those adapters are **not implemented**. It uses an undocumented Codex Desktop IPC protocol and the current app-server's `project/list`, `thread/start.projectId`, and `thread/metadata/update` methods for automatic sidebar grouping. It no longer needs a separate controller chat. Cloning and filling in Feishu credentials alone does not guarantee the exact desktop experience.

The optional local read profile can let bot chats inspect a specified product repository. Read-only Codex chat history access can also be enabled. General product answers, including safe summaries of authorized sources, reply automatically after local checks. Risky requests, including personal/private-project inquiries and code execution or service changes, first wait for per-request owner approval **in the same native Codex chat**. Flagged outgoing answers also wait for a native review: send the original answer, enter a complete replacement, or send nothing. External Feishu messages cannot substitute for an owner review-widget reply. Automated checks can miss confidential facts. See the Chinese guide for profile installation and test steps.

When a human question needs review, the bot sends one waiting message to the originating Feishu chat. Bot-to-bot questions do not generate waiting notices, which could otherwise trigger more automatic replies. The owner can write a clear natural-language request in the matching Codex chat to send a manual reply back to Feishu; the specified text is sent without an extra owner label. An ephemeral Codex classification pass extracts only an explicit outgoing message; ambiguous requests and draft requests remain local. Declining a review sends no rejection message to Feishu. Clearing Feishu's visible chat history does not reset the bridge's chat ID mapping; send `重新开始` or `重新开始：新问题` to start a new Codex chat.

Answers may be as detailed as the question requires. Source code, exact source paths, and verbatim excerpts require owner review before delivery. The default model is `gpt-6.1-sol` at `high` reasoning effort. Desktop loads each new chat once to acquire ownership; follow-up turns and reviews reuse that chat without repeated navigation.

Optional bot-to-bot questions use the existing Feishu event connection. Set `bot_messages_enabled` to `true`; the application needs `im:message.group_at_msg.include_bot:readonly`. Only group text/post messages with a real mention of this bot are accepted. Configure `bot_allowed_chat_ids` and `bot_allowed_sender_ids` to restrict groups and peers; empty lists accept any other bot that explicitly mentions this bot in a joined group. Replies quote the incoming message and mention its verified sender. The same group, peer, and reply chain reuse one Codex chat. Persistent topic counters default to three automatic turns per topic and six messages per peer per minute, with a 30-minute topic lifetime. Simple acknowledgements close a topic without another reply. The feature is disabled by default. Local tests do not replace a real two-bot acceptance test; see the Chinese guide for configuration and verification.

See the [Chinese setup guide](README.md) for architecture, prerequisites, installation, validation, limitations, and troubleshooting.
